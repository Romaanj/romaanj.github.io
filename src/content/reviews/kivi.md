    key_idea: 'K와 V는 통계적으로 다른 객체라는 관측이 전부를 결정한다. key cache는 소수의 고정 채널에 매우 큰 magnitude가 몰려 있어 per-token scale이 outlier 채널에 끌려간다 — 몇몇 픽셀이 항상 같은 자리에서 눈부신데 사진(토큰) 한 장마다 노출을 하나로 잡는 격이라, 그 열에 따로 노출을 주는 per-channel이 attention score 오차를 약 **5배** 줄인다. value cache는 outlier 패턴이 없는 대신 attention output이 소수 중요 토큰의 희소 가중합(측정 sparsity **84.3%**)이어서, 오차를 토큰 단위로 가두는 per-token이 output 오차를 약 **15배** 줄인다. 비대칭은 취향이 아니라 측정이 강제한 처방이다.'

  en:
    background: 'LLM serving amortizes cost via batching, but at large batch and long context the KV cache — not the weights — becomes the memory ceiling. Decode is memory-bound: every token must re-read the whole cache, leaving compute cores idle while it streams in — the cook is fast but the pantry is far, so meal speed is set by how quickly ingredients arrive. The existing detours split three ways: MQA/GQA cuts KV heads but needs training from scratch or fine-tuning, token eviction discards information, and quantization is the remaining axis.'
    problem: 'There was no way to push the KV cache to extreme low bit-width (2-bit, below 4-bit) without fine-tuning or calibration while preserving accuracy. The de-facto per-token quantization holds accuracy at INT4 but drops notably at INT2 (the paper''s observation OB1). So the real question becomes: what structural fact about KV tensors would permit 2 bits at all?'
    prior_limits: 'Prior KV quantization treated K and V identically — mostly per-token uniform, since new tokens append along the token axis and that is the only choice that trivially fits streaming decode (FlexGen''s 4-bit group-wise is the reference point; Atom-style schemes are also cited). The result was sharp collapse below 4 bits, with no in-depth study of KV cache element distributions. Per-channel was an essentially untried axis precisely because it appears to conflict with streaming.'
    goal: 'A tuning-free, plug-in 2-bit KV cache quantizer that keeps near-FP16 quality. Since the point is to convert the freed memory into larger batches and higher serving throughput, a hardware-friendly implementation compatible with streaming decode (kernel fusion included) is part of the method, not an accessory.'
    method: 'Quantize the key cache per-channel and the value cache per-token to 2 bits (group size **32**), keeping recent tokens as a full-precision residual: keys accumulate until **128** tokens (R) and are then quantized wholesale and concatenated into the 2-bit store, while values sit in a length-R queue whose oldest entry is popped and quantized per-token. Like a shop till: today''s takings (recent tokens) stay as cash in the drawer, and get deposited to the bank (the 2-bit store) in fixed bundles. This leaves a full-precision sliding window averaging R/2 tokens for keys and R for values, which the paper itself shows is crucial for hard tasks like GSM8K. Dequantization is fused into tiled matmul (the CUDA Q_MatMul kernel, plus Triton group-wise kernels), and the scheme composes with weight-only quantization.'
    key_idea: 'One observation decides everything: K and V are statistically different objects. The key cache concentrates very large magnitudes in a few fixed channels, so a per-token scale gets dragged by those outliers — like setting one exposure per photo (token) when a few pixels always glare in the same spots; giving those columns their own exposure, per-channel quantization cuts attention-score error by about **5x**. The value cache shows no outlier pattern, but the attention output is a sparse weighted sum over a few important tokens (measured sparsity **84.3%**), so per-token quantization confines error to individual tokens and yields about **15x** lower output error. The asymmetry is a prescription forced by measurement, not a design taste.'
    validation: 'Evaluated Llama/Llama-2 (7B, 13B), Falcon-7B, and Mistral-7B on LM-Eval (CoQA EM, TruthfulQA BLEU, GSM8K EM) and eight LongBench tasks (Qasper, QMSum, MultiNews, TREC, TriviaQA, SAMSum, LCC, RepoBench-P), plus Needle-in-a-Haystack retrieval checks on Llama-3-8B-Instruct and Mistral-7B-Instruct-v0.2. Closed-ended tasks like MMLU were deliberately excluded because a single decoding step cannot expose the effect of a compressed KV cache — a point still relevant to KV-compression evaluation design. Throughput follows the vLLM protocol: a ShareGPT-based synthetic workload (average input 161, output 338 tokens) on a single A100 80GB.'
    results: 'Maintains near-FP16 quality on most tasks — even on GSM8K, among the hardest generation tasks used, the drop is only about **2%** — while cutting peak memory (model weights included) by **2.6x** on Llama-2-7B. That memory saving converts into up to **4x** larger batches, giving **2.35-3.47x** higher throughput on the ShareGPT workload. Ablations show fine grouping itself matters at this bit-width: growing the group size from 32 to 128 drops GSM8K from 20.8 to **17.3**.'
    comparison: 'Compared against FP16, 4-bit per-token, and four fake 2-bit configurations. On Llama-2-13B CoQA, 2-bit per-token/per-token collapses from 66.4 to **52.9**, and any configuration that quantizes values per-channel implodes below **3%** regardless of how keys are handled (OB2). Only K per-channel + V per-token survives at 2 bits, and adding the full-precision sliding window on top lets KIVI recover most of the fake-quant GSM8K gap.'
    significance: 'It established the K/V asymmetry (per-channel K, per-token V) that most subsequent KV-cache quantization work inherits, deriving it explicitly from distribution measurements, and made a 2-bit KV cache a practical serving option. It is a textbook case of measuring the tensors first and letting the method fall out as a corollary, and its evaluation frame — memory saving converted into batch growth and then throughput — became standard for later work.'
    limitations: 'The paper itself reports that Falcon-7B (multi-query attention, a single KV head) is already highly compressed, so it degrades badly at 2 bits and needs 4-bit KIVI-4 — a signal that extreme-low-bit headroom depends on KV redundancy. Also (reviewer judgment) attribution of the full-precision window is blurry: the text calls a sufficiently large residual important, yet the R=32→128 sweep is nearly flat on GSM8K (20.6→20.8), suggesting the window''s existence, not its length, carries the effect. The paper also concedes non-zero quantization overhead during prefill and decoding.'
    future_work: 'The paper explicitly names deeper fusion of the KV quantization step with preceding operations, to cut prefill/decoding overhead, as future work. (Reviewer judgment) GQA models (Llama-3-8B-Instruct, Mistral-Instruct) are shown working in the appendix, but the outlier-channel analysis is not redone for GQA/MLA caches, so why the structure transfers remains open — as does how the asymmetric prescription reshapes when composed with eviction methods like H2O.'
    resources: 'Official code is on GitHub (jy-yuan/KIVI), built on HuggingFace Transformers and shipping the CUDA fused kernel (Q_MatMul) plus Triton group-wise quantization kernels. Being tuning-free and plug-in, it applies to existing checkpoints with no extra artifacts, and the KIVI-2 / KIVI-4 settings expose an accuracy-compression trade-off.'

## Notes

KIVI is the reference point for asymmetric KV-cache quantization: it turned a distributional observation — structured outlier channels in keys, none in values — into a quantization axis choice, and nearly every later KV-quant paper either inherits the per-channel-K/per-token-V split or defines itself against it. The full-precision residual window it introduced is now a standard ingredient, quietly doing accuracy work in most streaming low-bit schemes. Read alongside KVQuant for the non-uniform/outlier-isolation branch of the same problem, and H2O / DuoAttention for the orthogonal axis of dropping cache entries rather than shrinking them.

KIVI는 "tensor를 먼저 측정하고 method는 그 따름정리로 나온다"는 전개의 교과서적 사례로, KV quantization 계열을 읽을 때 출발점으로 삼기 좋은 논문이다.
